# 第 4 章：死锁

题目来源：[4_ProcessorScheduling.pdf](../../../../ppt/4_ProcessorScheduling.pdf#page=74)，PDF 第 74～78 页。以下保留题目条件，并按课件顺序作答。

银行家算法中，`Used` 表示已分配资源，`Need` 表示尚需资源：

$$
Need=Max-Used,\qquad Available=Total-\sum_i Used_i
$$

安全性检查令 $Work=Available$。若某个尚未完成的进程满足 $Need_i\le Work$（按分量比较），则可模拟其运行结束，并令 $Work\leftarrow Work+Used_i$。这里加回的是该进程原先占有的资源，因为临时借出的 `Need` 在完成时也会归还，二者相抵。

各题的资源请求小问均**从题给原始状态独立判断**。申请必须依次通过 `Request ≤ Need`、`Request ≤ Available` 和试分配后的安全性检查。不安全表示无法保证所有进程都按最大需求完成，不能直接等同于当前已发生死锁。

## 一、死锁作业 1（p74）

### 题目与初始状态

系统有 A、B、C 三类资源，总量分别为 5、11、11，使用银行家算法避免死锁。当前有 P1～P5 五个进程，最大需求与当前分配如下。

| 进程 | Max（A，B，C） | Used（A，B，C） | Need = Max − Used |
| --- | --- | --- | --- |
| P1 | (3, 5, 11) | (0, 2, 3) | (3, 3, 8) |
| P2 | (1, 6, 6) | (1, 3, 3) | (0, 3, 3) |
| P3 | (0, 2, 3) | (0, 1, 2) | (0, 1, 1) |
| P4 | (2, 8, 5) | (1, 1, 1) | (1, 7, 4) |
| P5 | (4, 4, 5) | (3, 2, 0) | (1, 2, 5) |

求当前状态是否安全，以及 P2 申请 (0, 1, 1)、P5 申请 (0, 1, 0) 时能否分配。

$$
\sum Used=(5,9,9),\qquad Available=(5,11,11)-(5,9,9)=(0,2,2)
$$

### （1）当前系统是否安全

| 步骤 | 选择进程 | 运行前 Work | 该进程 Need | 完成后 Work |
| --- | --- | --- | --- | --- |
| 1 | P3 | (0, 2, 2) | (0, 1, 1) | (0, 3, 4) |
| 2 | P2 | (0, 3, 4) | (0, 3, 3) | (1, 6, 7) |
| 3 | P5 | (1, 6, 7) | (1, 2, 5) | (4, 8, 7) |
| 4 | P4 | (4, 8, 7) | (1, 7, 4) | (5, 9, 8) |
| 5 | P1 | (5, 9, 8) | (3, 3, 8) | (5, 11, 11) |

每一步均满足 $Need_i\le Work$，因此**当前系统安全**，安全序列为：

$$
\boxed{P3\rightarrow P2\rightarrow P5\rightarrow P4\rightarrow P1}
$$

### （2）P2 申请 (0, 1, 1)

申请满足：

$$
(0,1,1)\le Need_2=(0,3,3),\qquad
(0,1,1)\le Available=(0,2,2)
$$

试分配后：

$$
Available'=(0,1,1),\quad Used_2'=(1,4,4),\quad Need_2'=(0,2,2)
$$

| 选择进程 | 运行前 Work | 该进程 Need | 完成后 Work |
| --- | --- | --- | --- |
| P3 | (0, 1, 1) | (0, 1, 1) | (0, 2, 3) |
| P2 | (0, 2, 3) | (0, 2, 2) | (1, 6, 7) |
| P5 | (1, 6, 7) | (1, 2, 5) | (4, 8, 7) |
| P4 | (4, 8, 7) | (1, 7, 4) | (5, 9, 8) |
| P1 | (5, 9, 8) | (3, 3, 8) | (5, 11, 11) |

仍存在安全序列 **P3 → P2 → P5 → P4 → P1**，所以**可以分配**。

### （3）P5 申请 (0, 1, 0)

申请满足：

$$
(0,1,0)\le Need_5=(1,2,5),\qquad
(0,1,0)\le Available=(0,2,2)
$$

试分配后：

$$
Available'=(0,1,2),\quad Used_5'=(3,3,0),\quad Need_5'=(1,1,5)
$$

此时只有 P3 的需求能够满足。模拟 P3 完成后：

$$
Work=(0,1,2)+(0,1,2)=(0,2,4)
$$

| 剩余进程 | Need | 无法满足的资源 |
| --- | --- | --- |
| P1 | (3, 3, 8) | A、B、C 均不足 |
| P2 | (0, 3, 3) | B 需要 3，只有 2 |
| P4 | (1, 7, 4) | A、B 不足 |
| P5 | (1, 1, 5) | A、C 不足 |

无法继续完成任何进程，故试分配后的状态不安全，**不能分配**；应撤销试分配，让 P5 等待。

## 二、死锁作业 2（p75）

### 题目与初始状态

系统有 A、B、C、D 四个进程，共享两类临界资源 R1、R2，总量分别为 12、8。最大需求和当前分配如下，判断当前状态是否安全并说明理由。

| 进程 | Max（R1，R2） | Used（R1，R2） | Need |
| --- | --- | --- | --- |
| A | (8, 2) | (3, 1) | (5, 1) |
| B | (3, 3) | (1, 2) | (2, 1) |
| C | (10, 2) | (2, 1) | (8, 1) |
| D | (7, 6) | (4, 3) | (3, 3) |

$$
\sum Used=(10,7),\qquad Available=(12,8)-(10,7)=(2,1)
$$

### 安全性检查

| 步骤 | 选择进程 | 运行前 Work | 该进程 Need | 完成后 Work |
| --- | --- | --- | --- | --- |
| 1 | B | (2, 1) | (2, 1) | (3, 3) |
| 2 | D | (3, 3) | (3, 3) | (7, 6) |
| 3 | A | (7, 6) | (5, 1) | (10, 7) |
| 4 | C | (10, 7) | (8, 1) | (12, 8) |

所有进程都能依次完成并释放资源，所以**当前状态安全**，安全序列为：

$$
\boxed{B\rightarrow D\rightarrow A\rightarrow C}
$$

## 三、死锁作业 3（p76）

### 题目与初始状态

系统有 A、B、C 三类临界资源，总量分别为 10、12、13，使用银行家算法避免死锁。当前有 P1～P5 五个进程，最大需求和当前分配如下。

| 进程 | Max（A，B，C） | Used（A，B，C） | Need |
| --- | --- | --- | --- |
| P1 | (9, 3, 5) | (3, 2, 1) | (6, 1, 4) |
| P2 | (5, 4, 5) | (2, 2, 2) | (3, 2, 3) |
| P3 | (7, 10, 2) | (1, 5, 2) | (6, 5, 0) |
| P4 | (3, 2, 4) | (0, 0, 4) | (3, 2, 0) |
| P5 | (4, 8, 7) | (0, 1, 3) | (4, 7, 4) |

求当前状态是否安全，以及 P2 申请 (1, 0, 1)、P5 申请 (1, 0, 0) 时能否分配。

$$
\sum Used=(6,10,12),\qquad Available=(10,12,13)-(6,10,12)=(4,2,1)
$$

### （1）当前系统是否安全

| 步骤 | 选择进程 | 运行前 Work | 该进程 Need | 完成后 Work |
| --- | --- | --- | --- | --- |
| 1 | P4 | (4, 2, 1) | (3, 2, 0) | (4, 2, 5) |
| 2 | P2 | (4, 2, 5) | (3, 2, 3) | (6, 4, 7) |
| 3 | P1 | (6, 4, 7) | (6, 1, 4) | (9, 6, 8) |
| 4 | P3 | (9, 6, 8) | (6, 5, 0) | (10, 11, 10) |
| 5 | P5 | (10, 11, 10) | (4, 7, 4) | (10, 12, 13) |

所以**当前系统安全**，安全序列为：

$$
\boxed{P4\rightarrow P2\rightarrow P1\rightarrow P3\rightarrow P5}
$$

### （2）P2 申请 (1, 0, 1)

申请满足：

$$
(1,0,1)\le Need_2=(3,2,3),\qquad
(1,0,1)\le Available=(4,2,1)
$$

试分配后：

$$
Available'=(3,2,0),\quad Used_2'=(3,2,3),\quad Need_2'=(2,2,2)
$$

| 选择进程 | 运行前 Work | 该进程 Need | 完成后 Work |
| --- | --- | --- | --- |
| P4 | (3, 2, 0) | (3, 2, 0) | (3, 2, 4) |
| P2 | (3, 2, 4) | (2, 2, 2) | (6, 4, 7) |
| P1 | (6, 4, 7) | (6, 1, 4) | (9, 6, 8) |
| P3 | (9, 6, 8) | (6, 5, 0) | (10, 11, 10) |
| P5 | (10, 11, 10) | (4, 7, 4) | (10, 12, 13) |

存在安全序列 **P4 → P2 → P1 → P3 → P5**，所以**可以分配**。

### （3）P5 申请 (1, 0, 0)

申请满足：

$$
(1,0,0)\le Need_5=(4,7,4),\qquad
(1,0,0)\le Available=(4,2,1)
$$

试分配后：

$$
Available'=(3,2,1),\quad Used_5'=(1,1,3),\quad Need_5'=(3,7,4)
$$

| 选择进程 | 运行前 Work | 该进程 Need | 完成后 Work |
| --- | --- | --- | --- |
| P4 | (3, 2, 1) | (3, 2, 0) | (3, 2, 5) |
| P2 | (3, 2, 5) | (3, 2, 3) | (5, 4, 7) |

初始只有 P4 能完成，随后只有 P2 能完成。此时剩余进程为：

| 剩余进程 | Need | 无法满足的资源 |
| --- | --- | --- |
| P1 | (6, 1, 4) | A 需要 6，只有 5 |
| P3 | (6, 5, 0) | A、B 不足 |
| P5 | (3, 7, 4) | B 需要 7，只有 4 |

不存在安全序列，所以**不能分配**；应撤销试分配，让 P5 等待。

## 四、死锁测试题 1（p77）

### 题目与初始状态

系统有 A、B、C 三类资源，总量分别为 17、5、20，使用银行家算法避免死锁。T0 时刻有 P1～P5 五个进程，状态如下。

| 进程 | Max（A，B，C） | Used（A，B，C） | Need |
| --- | --- | --- | --- |
| P1 | (5, 5, 9) | (2, 1, 2) | (3, 4, 7) |
| P2 | (5, 3, 6) | (4, 0, 2) | (1, 3, 4) |
| P3 | (4, 0, 11) | (4, 0, 5) | (0, 0, 6) |
| P4 | (4, 2, 5) | (2, 0, 4) | (2, 2, 1) |
| P5 | (4, 2, 4) | (3, 1, 4) | (1, 1, 0) |

1. 判断 T0 时刻是否安全，写出分析过程；若安全，给出安全序列。
2. 若 P4 请求 (2, 0, 1)，能否实施资源分配？为什么？

$$
\sum Used=(15,2,17),\qquad Available=(17,5,20)-(15,2,17)=(2,3,3)
$$

### （1）T0 时刻的安全性

| 步骤 | 选择进程 | 运行前 Work | 该进程 Need | 完成后 Work |
| --- | --- | --- | --- | --- |
| 1 | P4 | (2, 3, 3) | (2, 2, 1) | (4, 3, 7) |
| 2 | P2 | (4, 3, 7) | (1, 3, 4) | (8, 3, 9) |
| 3 | P3 | (8, 3, 9) | (0, 0, 6) | (12, 3, 14) |
| 4 | P5 | (12, 3, 14) | (1, 1, 0) | (15, 4, 18) |
| 5 | P1 | (15, 4, 18) | (3, 4, 7) | (17, 5, 20) |

因此 **T0 时刻是安全状态**，一个安全序列为：

$$
\boxed{P4\rightarrow P2\rightarrow P3\rightarrow P5\rightarrow P1}
$$

### （2）P4 请求 (2, 0, 1)

申请满足：

$$
(2,0,1)\le Need_4=(2,2,1),\qquad
(2,0,1)\le Available=(2,3,3)
$$

试分配后：

$$
Available'=(0,3,2),\quad Used_4'=(4,0,5),\quad Need_4'=(0,2,0)
$$

| 选择进程 | 运行前 Work | 该进程 Need | 完成后 Work |
| --- | --- | --- | --- |
| P4 | (0, 3, 2) | (0, 2, 0) | (4, 3, 7) |
| P2 | (4, 3, 7) | (1, 3, 4) | (8, 3, 9) |
| P3 | (8, 3, 9) | (0, 0, 6) | (12, 3, 14) |
| P5 | (12, 3, 14) | (1, 1, 0) | (15, 4, 18) |
| P1 | (15, 4, 18) | (3, 4, 7) | (17, 5, 20) |

试分配后仍存在安全序列 **P4 → P2 → P3 → P5 → P1**，因此**可以实施资源分配**。

## 五、死锁测试题 2（p78）：混合左右撇子的哲学家就餐

### 题目

哲学家就餐问题中，必须先拿左边筷子的哲学家称为左撇子，必须先拿右边筷子的哲学家称为右撇子。在左撇子和右撇子同时存在的前提下，让哲学家随意就座，会产生死锁吗？为什么？

### 解答

**在标准哲学家就餐模型下，不会产生死锁。** 这里沿用筷子互斥、先取得一支再申请另一支、用餐结束后释放两支筷子的规则。

如果发生死锁，等待关系必须形成闭环。每位哲学家只与左右邻座共享筷子，所以环形餐桌上的循环等待必须沿整圈闭合，即所有人都各持有一支筷子，再等待相邻者持有的另一支。

只要两种拿筷顺序同时存在，无论怎样就座，环上总能找到一对相邻哲学家，二者都把**他们之间的同一支筷子作为第一支筷子**。由于这支筷子是互斥资源，二者最多只有一人能取得它，另一人在申请第一支筷子时就会等待，手中没有筷子。

这个未持有筷子的哲学家无法成为“持有一支、等待另一支”的闭环成员，因此整圈循环等待不能形成。更小的进程子集也不能沿环形共享关系单独形成闭环。由此可知，混合两种拿筷顺序破坏了死锁所需的循环等待条件，任意就座均不会导致死锁。

这只说明不会发生死锁；若筷子的分配或进程调度不公平，个别哲学家仍可能长期得不到用餐机会，即发生饥饿。
